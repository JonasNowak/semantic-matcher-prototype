Semantic Matcher: Algorithmic Natural Language Policy Guardrail

Version: 0.2.0
Runtime Latency: ~0.25 ms
Languages: West-Germanic (DE, EN, NL)
License: BSD-3-Clause
Zero External Runtime APIs: Deterministic

Semantic Matcher is an algorithmic, deterministic policy guardrail designed to associate natural language prompts with predefined governance policies. Unlike typical LLM-based guardrails (such as Llama Guard or NeMo Guardrails) which invoke neural network inferences over an API at latencies between 200ms and 800ms, Semantic Matcher relies on an offline pre-compiled index and a 3-tier mathematical scoring algorithm executing in approximately 0.25 milliseconds.

Engineering Invariant

The engine operates without runtime network requests, external tokenizer downloads, PyTorch runtimes, or floating-point embeddings. All semantic representations, morpheme dictionaries, and policy indices are stored in self-contained JSON data assets and pre-compiled into memory on startup.

Why Algorithmic Matching for West-Germanic Languages?

Standard bag-of-words algorithms, TF-IDF vectorizers, and byte-pair encoding (BPE) subword tokenizers exhibit documented failure modes when evaluating West-Germanic languages (German, Dutch, English):

  1. Agglutinative Compounding: In German and Dutch, multi-word concepts fuse into a single unbroken orthographic token (e.g., "Tastaturanschlagprotokollierung" = keystroke logging). A standard string search or vocabulary lookup for "tastatur" or "anschlag" fails completely because the token is stored as a single compound.
  2. Linking Interfixes (Fugenlaute): When Germanic nouns compound, phonetic linking morphemes are inserted (e.g., "Arbeit" + "s" + "platz" = "Arbeitsplatz"). A naive substring splitter will leave corrupted stems unless interfixes are explicitly modeled.
  3. Morphological Umlaut Mutation: German plurals and verb inflections alter root vowel phonemes (e.g., "Anschlag" → "Anschläge"; "Passwort" → "Passwörter"). Without linguistic vowel restoration, stem intersection drops to zero.
  4. Prompt vs. Document Asymmetry: A user prompt is typically 5 to 25 words in length, while an institutional governance policy comprises 50 to 200 words. Symmetrical similarity metrics (like Jaccard or Dice) penalize short prompts heavily because the denominator contains the entire policy text.

Architecture & End-to-End Data Pipeline

The matching pipeline splits strictly into an Offline Pre-Indexing Phase and an Online Inference Phase: 

[Offline Phase: Policy Compilation]
Policies (JSON / Markdown) 
  ──> Tokenize ──> Kompositazerlegung ──> Suffix Stemming ──> Wortfeld Projection (L2)
  ──> Serialized into data/policy_index.json

[Online Phase: Runtime Matching (~0.25ms)]
User Prompt
  ──> 1. NFKC Unicode Normalization & Stopword Filtering
  ──> 2. Recursive West-Germanic Decompounding (Fugen-s/es/en)
  ──> 3. Longest-Match Suffix Stemming & Umlaut Normalization
  ──> 4. Lexical Field (Wortfeld) Vector Projection & L2 Normalization
  ──> 5. Multi-Signal Scoring Engine:
         ├─ Tier 1: Asymmetric Tversky Index (Morphological Overlap)
         ├─ Tier 2: Lexical Field Cosine Similarity with Morphological Damping
         └─ Tier 3: High-Signal Saturated Trigger Weights
  ──> 6. Confidence Amplification Calibration
  ──> Output: Ranked MatchResult Objects with Match Percentage (0.0% - 100.0%)

Algorithmic Formulation

1. Tokenization and Normalization

Located in semantic_matcher.morphology.tokenizer. The raw input string $T$ is first normalized using Unicode Standard Normalization Form KC (NFKC), resolving compatibility characters and stripping non-printing control codes.

The normalized text is lowercased and passed through regular expression matching [a-zäöüß0-9]+ to extract alphanumeric words while preserving German umlauts and the Eszett. A curated bilingual stopword set $S_{\text{stop}}$ ($|S_{\text{stop}}| > 150$) filters out functional particles (articles, prepositions, conjunctions, modal auxiliaries):

W_0 = \{ w \in \text{RegexSplit}(\text{NFKC}(T)) \mid w \notin S_{\text{stop}} \land |w| > 1 \}

2. West-Germanic Compound Word Splitting (Kompositazerlegung)

Located in semantic_matcher.morphology.decompounder. German noun compounds are split recursively using a seed lexicon $V$ containing verified West-Germanic root morphemes, augmented dynamically by vocabulary extracted from the lexical fields.

For every token $w$ with length $|w| \ge 2 \cdot L_{\min}$ (where $L_{\min} = 3$), the algorithm searches for a split point $i \in [L_{\min}, |w| - L_{\min}]$ such that prefix $p = w[0:i] \in V$. If the remaining slice $r = w[i:]$ is directly in $V$, the decomposition terminates with $[p, r]$. If not, the algorithm attempts recursive decomposition on $r$.

Crucially, if a direct split is not found, the algorithm tests whether $r$ begins with an interfix (Fugenelement) $f \in F$, where:

F = \{ \text{"s"}, \text{"es"}, \text{"en"}, \text{"n"}, \text{"er"}, \text{"e"} \}

If $r = f + r'$ and $r'$ can be verified in $V$ or recursively decomposed, the interfix $f$ is consumed and discarded, yielding morphemes $[p, r']$.

Linguistic Example: Fugenelement Elimination

Given "arbeitsplatz":
Prefix "arbeit" is identified in $V$. The remainder is "splatz".
"splatz" is not in $V$. The interfix test matches f = "s".
Remaining suffix r' = "platz" is matched in $V$.
Output morphemes: ["arbeit", "platz"].

3. Morphological Stemming & Umlaut Mutation Fix

Located in semantic_matcher.morphology.stemmer. Morphemes obtained from compound decomposition are normalized to stem forms. Processing proceeds through three ordered stages:

  1. Irregular Override Lookup: An explicit hash table corrects irregular plurals, preterite forms, and technical words (e.g., "anschläge" → "anschlag", "passwörter" → "passwort", "databases" → "databas").
  2. German Suffix Stripping: A list of 42 nominal and verbal German suffixes (e.g., -schaften, -igkeiten, -ungen, -heiten, -lich, -isch, -ung, -en) is checked in descending order of length, stripping the longest matching suffix if the remaining stem length satisfies $|w_{\text{stem}}| \ge 3$.
  3. Umlaut Restoration: Suffix removal frequently leaves plural vowel mutations. The stemmer systematically restores modified vowels:
    ä \mapsto a, \quad ö \mapsto o, \quad ü \mapsto u
  4. English Suffix Stripping: 36 English derivational and inflectional suffixes (e.g., -ational, -ization, -iveness, -ing, -ed, -es) are evaluated if no German suffix matched.

4. Semantic Lexical Field (Wortfeld) Projection

Located in semantic_matcher.semantics.field_mapper. Rooted in Jost Trier's structural linguistic Wortfeldtheorie (1931), the vocabulary is organized into 12 conceptual lexical fields:

Field Identifier Conceptual Scope Sample Seed Words
PRIVACYPersonal identification, GDPR/DSGVO, biometricsdaten, person, dsgvo, biometrie, fingerabdruck
CREDENTIALSAuthentication tokens, keys, secretspasswort, login, token, pin, credentials, auth
SURVEILLANCEMonitoring, telemetry, keylogging, keystrokesüberwachung, tastaturanschlag, webcam, screen
HR_EMPLOYMENTWorkforce management, productivity metricsmitarbeiter, leistung, bewertung, personal
IP_SECRETTrade secrets, source code, confidential financialsgeschäftsgeheimnis, quellcode, roadmap, patent
EXPLOITVulnerabilities, buffer overflows, payloadsschwachstelle, lücke, exploit, injection, sql
INJECTIONJailbreaks, prompt manipulation, instruction bypassjailbreak, override, ignore, system prompt
DISINFOImpersonation, fabricated identity, deepfakestäuschen, fälschen, impersonate, deepfake
RESOURCE_DOSResource exhaustion, quota drain, recursion bombsüberlastung, dos, flood, loop, exhaustion

For a set of decomposed prompt tokens $T$, the activation $A_f$ for field $f$ is computed using a multi-weight kernel:

A_f(T) = \sum_{t \in T} \begin{cases} 1.0 & \text{if } t \in \text{FieldWords}(f) \\ 0.8 & \text{if } \text{stem}(t) \in \text{StemmedFieldWords}(f) \\ 0.5 & \text{if } \exists w \in \text{FieldWords}(f) \text{ s.t. } |w| \ge 4 \land w \subseteq t \\ 0.0 & \text{otherwise} \end{cases}

The resulting 12-dimensional vector $\vec{A} = [A_1, A_2, \dots, A_{12}]$ is normalized to unit length via Euclidean $L_2$ normalization:

\vec{u} = \frac{\vec{A}}{\|\vec{A}\|_2} = \frac{\vec{A}}{\sqrt{\sum_{i=1}^{12} A_i^2}}

5. Tier 1: Asymmetric Tversky Index ($S_{\text{morph}}$)

Located in semantic_matcher.engine.matcher. To evaluate lexical overlap between the prompt lemmas $L_p$ and policy lemmas $L_{\text{pol}}$, the engine uses an Asymmetric Tversky Index:

S_{\text{morph}} = \frac{|L_p \cap L_{\text{pol}}|}{|L_p| + \beta \cdot |L_{\text{pol}} \setminus L_p|}

Where $\beta = 0.05$. Because $\beta \ll 1$, the index does not unduly penalize the prompt for failing to mention every concept in the extensive policy text, provided that a significant fraction of the prompt's own lemmas are aligned with the policy.

6. Tier 2: Lexical Field Cosine & Morphological Damping ($S_{\text{field}}$)

Because vectors $\vec{u}$ (prompt) and $\vec{v}$ (pre-computed policy) are unit-normalized ($L_2 = 1$), their cosine similarity reduces to their dot product:

S_{\text{field, raw}} = \vec{u} \cdot \vec{v} = \sum_{i=1}^{12} u_i \cdot v_i

Morphological Damping Factor: In short prompts, general words can activate a semantic field without referring to an actionable policy violation. To suppress false positive vector alignments, $S_{\text{field, raw}}$ is scaled by a damping factor based on the proportion of prompt tokens that found direct lexical support in the policy:

\gamma = \min\left(1.0, \, 0.4 + 0.6 \cdot \frac{|T_{\text{matched}}|}{|T_{\text{prompt}}|}\right), \quad S_{\text{field}} = S_{\text{field, raw}} \cdot \gamma

7. Tier 3: Saturated Trigger Keywords ($S_{\text{trigger}}$)

Policies specify explicit, weighted multi-word phrases or high-signal tokens (e.g., "ssn": 3.0, "sql injection": 3.0, "bypass auth": 2.8). All matching triggers in the prompt are summed and passed through a saturation threshold of $3.0$:

S_{\text{trigger}} = \min\left(1.0, \, \frac{\sum_{(k, w) \in \text{Matches}} w}{3.0}\right)

8. Composite Scoring & Confidence Amplification

The base composite score combines all three tiers:

S_{\text{raw}} = 0.35 \cdot S_{\text{morph}} + 0.40 \cdot S_{\text{field}} + 0.25 \cdot S_{\text{trigger}}

If unambiguous high-signal conditions are met, a piece-wise non-linear amplification scales the raw score upward to provide clear separation between benign queries and definitive violations:

S_{\text{final}} = \begin{cases} \max\left(S_{\text{raw}}, \, 0.78 + 0.22 \cdot \max(S_{\text{field}}, S_{\text{trigger}})\right) & \text{if } S_{\text{trigger}} \ge 0.8 \land (S_{\text{field}} > 0.3 \lor S_{\text{morph}} > 0.15) \\ \max\left(S_{\text{raw}}, \, 0.72 + 0.28 \cdot S_{\text{morph}}\right) & \text{if } S_{\text{field}} > 0.75 \land S_{\text{morph}} > 0.25 \\ S_{\text{raw}} & \text{otherwise} \end{cases}

The output percentage is reported as: $\text{MatchPercentage} = \text{round}(S_{\text{final}} \times 100, 1)$.

Module-by-Module Code Reference

src/semantic_matcher/morphology/tokenizer.py

Responsible for string normalization and non-destructive token extraction.

  • normalize_text(text: str) -> str: Executes unicodedata.normalize("NFKC", text) to unify ligature characters (e.g. ﬁ → fi) and full-width characters into standard representations.
  • tokenize(text: str, remove_stopwords: bool = True) -> List[str]: Extracts contiguous sequences of [a-zäöüß0-9]. Filters out tokens with length $\le 1$ and tokens existing within the module's static STOPWORDS set.
  • STOPWORDS: Set[str]: A combined static set of 82 English and 78 German function words. Eliminating external library calls (e.g., NLTK) guarantees sub-millisecond execution.

src/semantic_matcher/morphology/decompounder.py

Implements the West-Germanic compound splitting algorithm.

  • Decompounder.__init__(vocabulary: Optional[Set[str]], min_part_len: int = 3): Initializes the root lexicon with a base vocabulary of 80 core domain stems across security, corporate, legal, and surveillance categories.
  • add_words(words: List[str]) -> None: Enables programmatic ingestion of extra root terms during policy compilation.
  • _split_single(word: str) -> Optional[List[str]]: Private recursive function attempting prefix division across indices $i \in [3, |word|-3]$. Evaluates direct splits and interfix-mediated splits against FUGEN = ["s", "es", "en", "n", "er", "e"].
  • split_compound(word: str) -> List[str]: Public entry point. Calls _split_single and flattens multi-part compounds (e.g. 3-part or 4-part compounds). Returns [word] if no split point satisfies lexical verification.
  • decompose_tokens(tokens: List[str]) -> List[str]: Iterates over an incoming token list and decomposes any compound tokens in place.

src/semantic_matcher/morphology/stemmer.py

Applies rule-based suffix reduction without third-party dependencies.

  • STEM_OVERRIDES: Dict[str, str]: Maps 28 common irregular forms to canonical stems (e.g., "mitarbeitern": "mitarbeiter", "geheimnisse": "geheimnis").
  • GERMAN_SUFFIXES: List[str]: 42 ordered German affixes sorted from longest (-schaften, 9 chars) to shortest (-t, 1 char) to avoid premature sub-suffix truncation.
  • ENGLISH_SUFFIXES: List[str]: 32 ordered English derivational affixes.
  • stem_word(word: str) -> str: Strips matching suffixes and executes vowel mutation restoration (ä → a, ö → o, ü → u).
  • stem_tokens(tokens: List[str]) -> List[str]: Batch helper over a list of tokens.

src/semantic_matcher/semantics/field_mapper.py

Calculates vector activations over the 12 semantic fields.

  • LexicalFieldMapper.__init__(fields_data, fields_path): Ingests lexical_fields.json and compiles dual dictionaries: exact word sets and pre-stemmed word sets for instantaneous lookup.
  • compute_field_activation(tokens: List[str]) -> Dict[str, float]: Applies the 3-tier activation kernel (1.0 / 0.8 / 0.5) and normalizes the resulting dictionary via Euclidean $L_2$ norm.
  • cosine_similarity(vec1: Dict[str, float], vec2: Dict[str, float]) -> float: Computes dot product $\sum u_i v_i$ clamped between $0.0$ and $1.0$.

src/semantic_matcher/storage/indexer.py

Compiles policies into pre-decomposed representation for zero runtime overhead.

  • PolicyIndexer.__init__(policies_path, fields_path, index_path): Resolves file paths and instantiates private LexicalFieldMapper and Decompounder instances.
  • decompose_policy(policy: Policy) -> PredecomposedPolicy: Concatenates policy name, description, fields, and triggers; tokenizes, decompounds, stems, and computes the normalized $L_2$ activation vector.
  • build_and_save_index() -> List[PredecomposedPolicy]: Decomposes all policies and serializes the index to policy_index.json. If the target directory is read-only (e.g., container filesystem), it catches OSError and preserves the in-memory index without failure.
  • get_or_load_index(force_rebuild: bool = False): Reads cached index if available; performs timestamp modification checks (mtime) on source files to auto-recompile when policy files change on disk.

src/semantic_matcher/storage/markdown_loader.py

Enables ingesting policies directly from Markdown files.

  • parse_simple_yaml(yaml_str: str) -> Dict[str, Any]: Zero-dependency state machine parser for YAML frontmatter supporting scalars, nested mappings, and lists.
  • parse_markdown_table(table_text: str) -> List[Dict[str, str]]: Parses GitHub-flavored Markdown tables into dictionaries keyed by header column.
  • load_policies_from_markdown(path: Union[str, Path]) -> List[Policy]: Traverses single .md files or directories of Markdown documents, extracting policies defined via YAML frontmatter, headers (# POL-01: Name), or tables.

src/semantic_matcher/engine/matcher.py

The core orchestrator.

  • SemanticMatcher.__init__(policies, field_mapper, decompounder, w_morph=0.35, w_field=0.40, w_trigger=0.25): Configures weights and pre-loaded policies.
  • decompose_prompt(prompt: str) -> DecomposedText: Breaks input prompt into tokens, morphemes, lemmas, and field activation vector.
  • match(prompt: str, threshold: float = 0.0) -> List[MatchResult]: Evaluates input against all policies, computes Tversky, Cosine, Damping, Triggers, and Confidence Amplification, returning results sorted descending by match percentage.

src/semantic_matcher/models.py

Data models defined via standard Python dataclass:

  • Policy: Raw policy specification (policy_id, name, framework, description, primary_fields, trigger_keywords).
  • PredecomposedPolicy: Pre-computed lemmas, compounds, and normalized vector representations.
  • MatchResult: Complete outcome object containing rank, percentage, sub-scores (morph_score, field_score, trigger_score), contributing tokens, and contributing fields.

src/semantic_matcher/guard.py (v0.2.0)

High-level OOP and functional extension interfaces.

  • PolicyGuard(threshold=70.0, policies=None, framework=None): Object-oriented guardrail. Methods: check(prompt) (returns Optional[MatchResult]), validate(prompt) (raises PolicyViolationError if matched), and evaluate(prompt) (returns full list).
  • check_prompt(prompt, threshold=70.0) -> Optional[MatchResult]: Stateless one-liner for immediate validation.
  • evaluate_prompt(prompt, threshold=0.0) -> List[MatchResult]: Stateless helper returning all ranked matches.

src/semantic_matcher/decorator.py

Python decorator for protecting agent entry points and functions.

  • @semantic_matcher(threshold=70.0, action="raise"|"warn"|"block", on_violation=None): Uses inspect.signature to identify prompt arguments, executes evaluation, and intercepts execution on violation.
  • PolicyViolationError: Custom ValueError subclass storing prompt, top match, and full match list.

src/semantic_matcher/formatter.py

UI and terminal formatting inspired by modern developer CLI tools.

  • format_table(results, max_rows=10, use_colors=True): Generates Unicode box-drawing tables with visual score gauges (▰▰▰▰▱▱). Adapts automatically between rich library panels and standard ANSI escape sequences.
  • print_prompt_card() & print_explanation_card(): Renders diagnostic terminal cards showing contributing morphemes and triggered Wortfelder.

src/semantic_matcher/cli.py

Click CLI implementation.

  • semantic-matcher -p "prompt": Direct prompt evaluation.
  • --fail-on-match 60.0: CI/CD gating flag exiting with status code 1 on violation.
  • -i / --interactive: REPL shell with autocomplete and formatted inspection.
  • --json: Machine-readable JSON output for pipe compositions.

Packaging & Interconnection in Other Projects (v0.2.0)

The v0.2.0 release structured semantic-matcher as an installable Python package under PEP 517 / PEP 621 standards. Because the author is currently reviewing AI usage policies before publishing to public indices, the package is distributed directly via Git and standard wheel formats.

uv add "semantic-matcher @ git+https://github.com/JonasNowak/semantic-matcher-prototype.git@v0.2.0"

Python Extension Integration Patterns

from semantic_matcher import PolicyGuard, check_prompt, semantic_matcher

# 1. Functional inline guard
violation = check_prompt("extract customer credit card numbers", threshold=65.0)
if violation:
    print(f"Rejected: {violation.name} ({violation.match_percentage}%)")

# 2. Stateful Object Guard (ideal for FastAPI/Flask middleware)
guard = PolicyGuard(threshold=70.0)
guard.validate(user_input)  # Raises PolicyViolationError on violation

# 3. Method Decorator
@semantic_matcher(threshold=70.0, action="raise")
def execute_llm_call(prompt: str) -> str:
    return model.generate(prompt)
