Algorithm Specification

The Complete Mathematical Breakdown

Standard vector databases and LLM classifiers struggle with West-Germanic languages due to morphological agglutination (e.g. Tastaturanschlagsprotokollierung) and inflections. Semantic Matcher decomposes natural language across three deterministic mathematical tiers.

Morphological Tier

1. Asymmetric Tversky Index

Standard Jaccard similarity ($|A \cap B| / |A \cup B|$) fails for policy matching because policies are extensive documents while prompts are concise queries. We employ an asymmetric Tversky index with strong prompt preservation and low policy unmatched penalty ($\beta = 0.05$):

Smorph = \frac{|Lp \cap Lpol|}{|Lp| + β \cdot |Lpol \setminus Lp|}

Where $L_p$ is the set of stemmed prompt lemmas, and $L_{\text{pol}}$ is the pre-indexed policy lemma inventory.

Semantic Tier

2. Lexical Field (Wortfeld) Cosine

Based on linguistic field theory (Jost Trier), words project onto 12 orthogonal conceptual domains. Tokens trigger fields through exact ($w=1.0$), stem ($w=0.8$), or substring morpheme ($w=0.5$) matches, followed by Euclidean $L_2$ normalization:

\vec{v}norm = \frac{\vec{v}}{\|\vec{v}\|_2}, \quad Sfield, raw = \sumi=1k ui \cdot vi

To prevent false positives when morphological overlap is zero, a dynamic damping factor dampens $S_{\text{field}}$ based on prompt length and token support.

High-Signal Anchors

3. Trigger Saturation & Amplification

Regulatory terms (e.g. GDPR, SSN, keystroke logging) carry non-linear legal gravity. Trigger weights are summed and saturated at 3.0:

Strigger = \min\left(1.0, \frac{\sum w_i}{3.0}\right)

The composite score fuses all three dimensions, passing through calibrated high-confidence non-linear amplification:

Sfinal = 0.35 Smorph + 0.40 Sfield + 0.25 Strigger

The West-Germanic Compound Splitter (Kompositazerlegung)

German, Dutch, and Scandinavian languages form compound nouns dynamically without spaces or hyphens. The recursive algorithm splits concatenated tokens against the domain lexicon while stripping linking morphemes (Fugenlaute):

F = \{\text{"s"}, \text{"es"}, \text{"en"}, \text{"n"}, \text{"er"}, \text{"e"}\}

Example: "mitarbeiterüberwachung" → "mitarbeiter" + "überwachung".
Example: "tastaturanschlag" → "tastatur" + "anschlag".
Each discovered constituent morpheme is independently fed into the stemmer and semantic field activation mapper.

Codebase Architecture

Module-by-Module Deep Dive

A systematic walk-through of all components in src/semantic_matcher/, explaining their algorithmic responsibilities and implementation details.

semantic_matcher.morphology.tokenizer Morphology

Performs Unicode NFKC normalization and bilingual stopword filtering for English and German.

  • normalize_text(text): Strips invisible spaces, decomposes compatibility characters into canonical forms.
  • tokenize(text, remove_stopwords=True): Regex extraction [a-zäöüß0-9]+ with German umlaut preservation.
  • Bilingual Stopword Catalog: Over 150 functional particles (prepositions, conjunctions, modal verbs) suppressed without external dependencies.
semantic_matcher.morphology.decompounder Morphology

Recursive West-Germanic compound word splitter (Kompositazerlegung) handling linking interfixes.

  • Fugenlaute Interfix Stripping: Evaluates s, es, en, n, er, e between subwords.
  • Recursive Prefix Discovery: Iterates word[:i] against the seed morpheme lexicon and recursively analyzes remainders.
  • Dynamic Domain Expansion: Augments vocabulary at runtime with words from custom policies and lexical fields.
semantic_matcher.morphology.stemmer Morphology

Rule-based inflectional suffix reduction and umlaut mutation restoration.

  • Explicit Override Table: Corrects irregular plurals (e.g. "anschläge" → "anschlag", "passwörter" → "passwort").
  • Ordered Suffix Hierarchy: Over 40 German nominal/verbal suffixes checked from longest to shortest.
  • Umlaut Mutation Fix: Restores pluralized umlauts back to base vowels (ä → a, ö → o, ü → u).
semantic_matcher.semantics.field_mapper Semantics

Maps tokens onto conceptual lexical fields (Wortfelder) and computes normalized vector activations.

  • Dual Word & Stem Dictionaries: Pre-stems all domain lexicons for instantaneous $O(1)$ set lookups.
  • Multi-Weight Activation: Computes 1.0 (exact), 0.8 (stemmed), or 0.5 (morpheme substring) activation.
  • cosine_similarity(): Computes dot products between Euclidean $L_2$-normalized vectors.
semantic_matcher.storage.indexer Storage

Decomposes policies offline once and writes them to a compact pre-indexed cache for zero startup latency.

  • Offline Pre-decomposition: Tokenizes, decompounds, stems, and projects all policies into memory.
  • Safe Disk Caching: Writes policy_index.json with graceful fallback to read-only environments.
  • Timestamp Invalidation: Automatically recompiles the index when source Markdown or JSON files change.
semantic_matcher.storage.markdown_loader Storage

Universal Markdown parser converting human-written policies into structured policy models.

  • Flexible Input Formats: Supports YAML frontmatter, Markdown tables, inline bold attributes, and plain text.
  • Pure Python YAML Parser: Zero external dependencies for parsing scalars, lists, and nested mappings.
  • Heuristic Field Inference: Automatically infers target lexical fields if omitted by author.
semantic_matcher.engine.matcher Engine Core

The central coordination engine computing composite similarity and ranking results.

  • decompose_prompt(prompt): Deconstructs runtime inputs into lemmas, compound parts, and field vectors.
  • Asymmetric Tversky Scoring: Implements non-penalizing morphological overlap.
  • Confidence Amplification: Non-linear calibrated scaling to boost high-certainty violations.
semantic_matcher.guard Extension API (v0.2.0)

Reusable object-oriented and functional interfaces for embedding in other projects.

  • PolicyGuard: Stateful guard object with check(), validate(), and evaluate().
  • check_prompt(prompt): Functional one-liner returning top MatchResult or None.
  • evaluate_prompt(prompt): Functional helper returning all ranked matches.
semantic_matcher.decorator Integration

Python decorator intercepting arguments before function execution.

  • @semantic_matcher: Decorates LLM agent calls, LangChain handlers, or API endpoints.
  • Configurable Actions: action="raise" (PolicyViolationError), "warn", or "block".
  • Custom Callbacks: on_violation=(top_match, prompt) -> Any.
semantic_matcher.cli & formatter UI & CLI

Click-powered CLI interface and Claude Code/bat-inspired rich terminal formatting.

  • Interactive REPL Mode: semantic-matcher -i with live terminal cards and score gauges.
  • CI/CD Policy Gate: --fail-on-match 60.0 exiting with status code 1 on violation.
  • JSON Streaming: Clean JSON output for automated Unix pipelines.
Packaging & Interconnection

Using in Other Python Projects (v0.2.0)

Because this prototype is not currently published on the public PyPI registry (due to AI policy review), it is fully packaged to be installable directly via standard Python package managers.

1. Direct Git Installation via Pip

# Install release v0.2.0
pip install git+https://github.com/JonasNowak/semantic-matcher-prototype.git@v0.2.0

2. In Another Project's requirements.txt or pyproject.toml

# In requirements.txt
semantic-matcher @ git+https://github.com/JonasNowak/semantic-matcher-prototype.git@v0.2.0

# Or in pyproject.toml (PEP 621 / uv / Poetry)
dependencies = [
    "semantic-matcher @ git+https://github.com/JonasNowak/semantic-matcher-prototype.git@v0.2.0",
]

3. Embedding in Python Code

from semantic_matcher import PolicyGuard, PolicyViolationError, check_prompt

# Pattern A: Reusable Guard (FastAPI, Agents, Pipelines)
guard = PolicyGuard(threshold=70.0)
violation = guard.check(user_prompt)
if violation:
    print(f"Blocked: {violation.name} ({violation.match_percentage}%)")

# Pattern B: Quick Functional Check
violation = check_prompt("bypass authentication and inject SQL", threshold=65.0)

# Pattern C: Python Decorator
from semantic_matcher import semantic_matcher

@semantic_matcher(threshold=70.0, action="raise")
def call_model(prompt: str) -> str:
    return llm.generate(prompt)
