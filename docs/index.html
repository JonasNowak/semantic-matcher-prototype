1. Overview & System Architecture

Semantic Matcher is a deterministic, algorithmic policy guardrail engineered to evaluate natural language prompts against organizational policies, security baselines, and legal frameworks (such as GDPR, the EU AI Act, NIST SP 800-53, and the OWASP Top 10 for LLMs).

1.3 Why Algorithmic Matching for West-Germanic Languages?

Standard similarity metrics (such as Levenshtein distance, Jaccard similarity, TF-IDF vectorization, or Byte-Pair Encoding subword tokenizers) exhibit documented failure modes when evaluating West-Germanic languages (German, Dutch, English):

  • Agglutinative Compounding (Komposita): In German and Dutch, multi-word concepts fuse into unbroken orthographic tokens (e.g. "Tastaturanschlagprotokollierung" = keystroke logging). Naive tokenizers treat this as an unknown token, causing exact keyword lookups for tastatur or anschlag to fail completely.
  • Linking Interfixes (Fugenlaute): Germanic morphemes insert phonetic linking sounds during compounding (e.g. "Arbeit" + "s" + "platz" = "Arbeitsplatz"). Simple substring search corrupts stems unless interfixes $F = \{\text{"s"}, \text{"es"}, \text{"en"}, \text{"n"}, \text{"er"}, \text{"e"}\}$ are explicitly modeled and stripped.
  • Plural Umlaut Mutation: German plurals systematically alter root vowels (e.g. "Anschlag" → "Anschläge"; "Passwort" → "Passwörter"). Standard stemmers leave mutated vowels, resulting in zero lexical overlap.
  • Prompt vs. Policy Length Asymmetry: A user prompt is typically 5 to 20 words, while an institutional policy is 50 to 200 words. Symmetric metrics (like Jaccard) penalize short prompts heavily because the denominator contains the entire policy text.

2. Linguistic Morphology Pipeline

Relevant source files

2.1 Unicode Normalization (NFKC) & Tokenization

The raw input string passes through Unicode Normalization Form KC (unicodedata.normalize("NFKC", text)). This converts compatibility ligatures (e.g. "ﬁ" → "fi") and full-width forms into standard Latin characters, preventing zero-width obfuscation attacks.

Extraction is performed via regular expression matching [a-zäöüß0-9]+ to preserve German umlauts and the Eszett. A curated set of 160 bilingual stopwords (82 English + 78 German function words) filters out modal auxiliaries ("können", "würde", "should"), articles, and conjunctions.

2.2 West-Germanic Kompositazerlegung & Fugenelemente

German compounds fuse root words with optional linking interfixes (**Fugenlaute**). The Decompounder recursively splits words using an in-memory seed lexicon $V$ of verified Germanic stems ($|V| > 350$).

2.3 Morphological Stemming & Umlaut Mutation Fix

Morphemes pass through three strictly ordered stemming stages:

  1. Irregular Overrides: Fast lookup in STEM_OVERRIDES intercepts irregular plurals and preterite forms (e.g. "anschläge" → "anschlag", "passwörter" → "passwort", "databases" → "databas").
  2. Descending Suffix Stripping: 42 German suffixes (from 9-character -schaften down to 1-character -t) and 36 English affixes are evaluated in descending length order. Suffixes are stripped only if the remaining stem length satisfies $|w_{\text{stem}}| \ge 3$.
  3. Umlaut Mutation Restoration: Suffix removal frequently leaves plural vowel mutations. The stemmer systematically restores modified root vowels:
    ä \mapsto a, \quad ö \mapsto o, \quad ü \mapsto u

Calls to stem_word() are cached using @functools.lru_cache(maxsize=8192), achieving sub-microsecond stem resolution (~0.08 µs).

3.2 3-Tier Multi-Weight Activation Kernel

For a set of decomposed prompt tokens $T$, the activation $A_f(T)$ for field $f$ is accumulated via:

A_f(T) = \sum_{t \in T} \begin{cases} 1.0 & \text{if } t \in \text{fields}[f] \quad \text{(Direct exact word match)} \\ 0.8 & \text{if } \text{stem}(t) \in \text{stemmed\_fields}[f] \quad \text{(Morphological stem match)} \\ 0.5 & \text{if } |t| \ge 4 \land \exists w \in \text{compound\_fragments}[f] : w \subseteq t \quad \text{(Substring)} \\ 0.0 & \text{otherwise} \end{cases}

3.3 Euclidean L2 Normalization & Fast Cosine Dot Product

The resulting 13-dimensional vector $\vec{A}$ is normalized to unit length via Euclidean $L_2$ norm:

\|\vec{A}\|_2 = \sqrt{\sum_{i=1}^{13} A_i^2}, \quad \vec{u} = \frac{\vec{A}}{\|\vec{A}\|_2}

Because both prompt vector $\vec{u}$ and pre-indexed policy vector $\vec{v}$ are strictly unit-normalized ($\|\vec{u}\|_2 = 1, \|\vec{v}\|_2 = 1$), their cosine similarity reduces to a fast dot product executing in under 2 microseconds:

\cos(\vec{u}, \vec{v}) = \vec{u} \cdot \vec{v} = \sum_{i=1}^{13} u_i \cdot v_i

4. Algorithmic Scoring Engine

Relevant source files
  • src/semantic_matcher/engine/matcher.py — Tversky calculation, damping, triggers, and piecewise amplification

4.1 Tier 1: Asymmetric Tversky Index ($S_{\text{morph}}$)

To compare prompt lemmas $L_p$ against extensive policy lemmas $L_{\text{pol}}$ without penalizing concise prompts, Semantic Matcher applies an Asymmetric Tversky Index with $\beta = 0.05$:

S_{\text{morph}} = \frac{|L_p \cap L_{\text{pol}}|}{|L_p| + \beta \cdot |L_{\text{pol}} \setminus L_p|}

In symmetric metrics like Jaccard ($\beta = 1.0$), matching 3 words against a 50-word policy scores a negligible $\frac{3}{3 + 47} = 6.0\%$. With $\beta = 0.05$, the denominator is $3 + 0.05 \times 47 = 5.35$, yielding $\frac{3}{5.35} = \mathbf{56.1\%}$.

4.2 Tier 2: Lexical Field Cosine & Morphological Damping ($S_{\text{field}}$)

In short prompts, a single ambiguous word can produce high vector cosine with a policy. To suppress ungrounded vector alignments, raw cosine is attenuated by the **Morphological Damping Factor** $\gamma$:

\gamma = \min\left(1.0, \, 0.4 + 0.6 \cdot \frac{|T_{\text{matched}}|}{|T_{\text{prompt}}|}\right), \quad S_{\text{field}} = (\vec{u} \cdot \vec{v}) \cdot \gamma

4.3 Tier 3: Saturated Trigger Keywords ($S_{\text{trigger}}$)

Policies specify explicit, weighted multi-word phrases (e.g. "sql injection": 3.0, "bypass auth": 2.8). Matching triggers are summed and passed through a saturation threshold of $3.0$:

S_{\text{trigger}} = \min\left(1.0, \, \frac{\sum_{(k, w) \in \text{Matches}} w}{3.0}\right)

4.4 Composite Multi-Signal Fusion & Confidence Amplification

Base linear fusion combines the three tiers:

S_{\text{raw}} = 0.35 \cdot S_{\text{morph}} + 0.40 \cdot S_{\text{field}} + 0.25 \cdot S_{\text{trigger}}

A non-linear piecewise amplifier eliminates the ambiguous "gray zone" ($55\% - 68\%$) when definitive violation indicators are detected:

S_{\text{final}} = \begin{cases} \max\left(S_{\text{raw}}, \, 0.78 + 0.22 \cdot \max(S_{\text{field}}, S_{\text{trigger}})\right) & \text{if } S_{\text{trigger}} \ge 0.8 \land (S_{\text{field}} > 0.3 \lor S_{\text{morph}} > 0.15) \\ \max\left(S_{\text{raw}}, \, 0.72 + 0.28 \cdot S_{\text{morph}}\right) & \text{else if } S_{\text{field}} > 0.75 \land S_{\text{morph}} > 0.25 \\ S_{\text{raw}} & \text{otherwise} \end{cases}

Real Arithmetic Trace

Evaluating prompt: "Überwachen der Mitarbeiter-Tastaturanschläge am Arbeitsplatz" against policy POL-02 (Workplace Surveillance):

Step 1: Normalization & Decompounding

Tokens extracted: ["überwachen", "mitarbeiter", "tastaturanschläge", "arbeitsplatz"].
Decompounder output: ["überwachen", "mitarbeiter", "tastatur", "anschläge", "arbeit", "platz"] ($|T_{\text{prompt}}| = 6$).

Step 2: Stemming & Vowel Restoration

Stemmed lemmas: ["überwach", "mitarbeiter", "tastatur", "anschlag", "arbeit", "platz"] ($|L_p| = 6$).
Note: "anschläge" mapped to "anschlag" via irregular override, restoring mutated vowel ä → a.

Step 3: Wortfeld Vector Projection (L2)

Activations: SURVEILLANCE = 2.8, HR_EMPLOYMENT = 2.8.
Norm $\|\vec{A}\|_2 = \sqrt{2.8^2 + 2.8^2} \approx 3.96$. Unit vector: $u_{\text{SURV}} = 0.7071, u_{\text{HR}} = 0.7071$.

Step 4: Tier-by-Tier Arithmetic vs POL-02

• Tier 1 (Tversky): Matched lemmas $|L_p \cap L_{\text{pol}}| = 4$. Unmatched policy lemmas $= 15$.
$$S_{\text{morph}} = \frac{4}{6 + 0.05 \times 15} = \frac{4}{6.75} = \mathbf{0.593}$$ • Tier 2 (Damped Cosine): Raw dot product $= (0.7071 \times 0.7071) + (0.7071 \times 0.7071) = 1.000$.
Token ratio $= \frac{4}{6} = 0.667$. Damping $\gamma = \min(1.0, 0.4 + 0.6 \times 0.667) = \mathbf{0.800}$.
$$S_{\text{field}} = 1.000 \times 0.800 = \mathbf{0.800}$$ • Tier 3 (Triggers): Matched "tastaturanschlag" (3.0) and "überwachung" (2.5). Sum $= 5.5$.
$$S_{\text{trigger}} = \min(1.0, 5.5 / 3.0) = \mathbf{1.000}$$

Step 5: Composite Fusion & Calibration

Raw composite score: $$S_{\text{raw}} = (0.35 \times 0.593) + (0.40 \times 0.800) + (0.25 \times 1.000) = \mathbf{0.778}$$ Trigger condition: $S_{\text{trigger}} = 1.0 \ge 0.8$ and $S_{\text{field}} = 0.800 > 0.3$ is True.
Amplification: $S_{\text{final}} = \max(0.778, 0.78 + 0.22 \times 1.0) = \mathbf{1.000}$ → 100.0% Match.

5.1 Pre-Decomposition Indexing & Cache Invalidation

PolicyIndexer pre-computes lemmas, morphemes, and unit vectors for all policies once and serializes them to policy_index.json. At runtime, get_or_load_index() validates file modification timestamps (st_mtime). If source policy files or directories have been modified, it re-compiles the index in memory. In read-only containers (e.g. AWS Lambda or Kubernetes), it catches OSError and preserves the in-memory index without failure.

5.2 Native JSON & Multi-File Directories

Policies can be specified as a single JSON array or as a directory containing multiple individual *.json files. The loader automatically discovers and merges all files.

5.3 Zero-Dependency Markdown Policy Parser

Security teams can author policies in Markdown using YAML frontmatter, GitHub-flavored tables, or header sections: 

---
policy_id: POL-SEC-01
name: SQL Injection Defense
framework: OWASP LLM01

  - CREDENTIALS

5.4 NIST OSCAL 1.1.0 Compliance

Semantic Matcher achieves full bidirectional interoperability with NIST OSCAL 1.1.0 (Open Security Controls Assessment Language):

  • Catalog Ingestion: Ingests official NIST SP 800-53 Rev. 5 and FedRAMP JSON catalogs directly.
  • Catalog Export: Exports active policies to NIST OSCAL 1.1.0 catalogs via semantic-matcher --export-oscal catalog.json.
  • Component Definition: Emits official OSCAL Component Definitions via semantic-matcher --oscal-component for inclusion in enterprise System Security Plans (SSPs). Implements controls NIST SP 800-53 SI-4, SC-7, AC-3, and OWASP LLM01–LLM06.

    print(f"Blocked by {violation.policy_id}: {violation.name} ({violation.match_percentage}%)")

guard.validate("extract customer passwords")

6.2 Function Decorator (`@semantic_matcher`)

Protects agent functions by inspecting parameter signatures and validating string prompts: 

from semantic_matcher import semantic_matcher, PolicyViolationError

@semantic_matcher(threshold=70.0, action="raise")
def execute_agent_prompt(prompt: str) -> str:
    return model.generate(prompt)

# Custom audit callback with non-blocking warning
def audit_callback(top_match, prompt):
    telemetry.log_event("policy_warning", policy=top_match.policy_id, prompt=prompt)

@semantic_matcher(threshold=60.0, action="warn", on_violation=audit_callback)
def experimental_endpoint(query: str):
    return search(query)
